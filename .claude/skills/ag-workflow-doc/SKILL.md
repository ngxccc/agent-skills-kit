# Grounded Workflow Documentation Skill (`ag-workflow-doc`)

> **Operational Purpose:** Generates publish-grade feature and infrastructure workflow specifications conforming to the SSOT Workflow Documentation Standard at `process/development-protocols/references/workflow-documentation-standard.md`. Employs Codebase Memory MCP graph search tools (`search_graph`, `trace_path`, `get_code_snippet`, `get_architecture`) for deep grounding.

---

## 1. Document Archetypes

All Workflow Docs generated by this skill MUST specify one of two `docType` archetypes in frontmatter:

1. **`docType: feature-workflow`**: Business features (Auth, Booking, Payment, Webhook, Wallet). Includes 4-level Markdown WBS breakdown, sequence diagram, DTO/Service logic, and security strategy.
2. **`docType: infrastructure-workflow`**: Cross-cutting technical components (Exception Filters, Guards, Interceptors, Relay). Includes architectural goals, exception sequence, implementation blueprint, and production leak audit.

---

## 2. Mandatory File Naming Standard (`kebab-case`)

All generated workflow files MUST use strict **kebab-case**:

- **Target Directory:** `docs/design/` (Canonical SSOT Location).
- **Naming Pattern:** `<feature-slug>-<topic-slug>-workflow.md` or `<component-name>-workflow.md`.
- **Examples:**
  - `docs/design/booking-payment-workflow.md`
  - `docs/design/global-exception-filter-workflow.md`
  - `docs/design/jwt-auth-guard-workflow.md`

---

## 3. Structural Rules & Execution Steps

### Step 1: Codebase Memory MCP Grounding
Before drafting, query the codebase knowledge graph:
- Use `search_graph` to find relevant handlers, services, DTOs, and schemas.
- Use `trace_path` to map inbound and outbound caller dependencies.
- Use `get_code_snippet` to retrieve verbatim signatures and DTO structures.

### Step 2: 4-Level Work Breakdown Structure (WBS Table)
Include a structured Markdown WBS table:
- **L1:** Module boundary (`1.0`)
- **L2:** Component / Endpoint (`1.1`)
- **L3:** Logic layer / Guard / Service (`1.1.1`)
- **L4:** Execution subtasks / Queries / DTO transformation (`1.1.1.1`)

### Step 3: Autonumbered Mermaid Sequence Diagram
Include an autonumbered sequence diagram mapping actor, controller, service, DB/Outbox, and external API interactions.

### Step 4: Defense-in-Depth & Implementation Checklist
Detail rate-limiting, DTO sanitization, security boundaries, and step-by-step verification checklists.
